- PERMISOS DE USUARIOS: SE PODRA ACCEDER A OPCIONES DE PERMISOS PARA USUSARIOS MEDIANTE UN BOTON (NOSE SI ES PARTE DEL MODULO ESTE O ES OTRO, Y SI ES UN MODULO INDEPENDIENTE DENTRO DE ESTE),

- al seleccionar la opcion de permisos (puede ser un boton)
- se desplegara una opcion visual para seleccionar un ususario en el mismo panel de ususarios
- al seleccionar un usuario aparecera un panel con los modulos y en cada uno sus permisos/acciones
- para trabajar con ese modulo y panel se utilizaran las siguientes tablas en la base de datos 
    permisos_usuarios (sera una tabla relacional para ususarios/permisos_modulos, esta tabla va a identificar que usuario tiene permitido acciones dentro de los modulos)
    permisos_modulos (funcionara como catalogo de todos los permisos y en donde se menciona el modulo y su accion)
    usuarios (sera la tabla resspectiva donde se registrara la informacion de todos los ususarios)


Cuando CREAS un usuario:El backend toma los datos personales (nombre, cédula, etc.) y los guarda en la tabla usuarios.  Al guardarlo, la base de datos le genera automáticamente su nuevo id_usuario (supongamos que le asigna el ID 50).  Luego, el backend hace un ciclo (un for) leyendo el arreglo idsPermisos que mandó el frontend. Si el frontend mandó [1, 2], el backend inserta dos filas en la tabla permisos_usuarios:  Fila 1: id_usuario = 50 y id_permisom = 1.  Fila 2: id_usuario = 50 y id_permisom = 2.  

Cuando EDITAS un usuario:El frontend envía la petición a la URL que ya tiene el ID del usuario, por ejemplo: /api/usuarios/50. ¡Ahí el backend ya sabe de qué usuario estamos hablando!  El backend va a la tabla permisos_usuarios y borra todos los permisos viejos que tenía el usuario 50.  Vuelve a hacer el ciclo (el for) con el nuevo arreglo idsPermisos y guarda las nuevas parejas en la tabla permisos_usuarios (ej: id_usuario = 50 con el nuevo id_permisom).  

El flujo exacto que hace el frontend es el siguiente antes de que el usuario interactúe con el formulario:Consulta previa: Cuando el usuario abre la pantalla de crear o editar un usuario, lo primero que hace el frontend es llamar a la Ruta 5 (GET /api/usuarios/permisos/catalogo).  Recepción de la lista: Tu backend le responde con una lista de todos los permisos disponibles en la base de datos. Por ejemplo:  JSON{
  "data": [
    { "id_permisom": 1, "modulo": "gestion_usuarios", "accion": "ver" },
    { "id_permisom": 2, "modulo": "gestion_usuarios", "accion": "crear_editar" }
  ]
}
Pintar la interfaz: El frontend toma esa respuesta y "pinta" los checkboxes o interruptores en la pantalla usando esos nombres (ver, crear_editar), pero por dentro guarda el id_permisom asociado a cada cajita (el 1 y el 2).Armar el envío: Cuando el operador marca o desmarca los permisos en el formulario y hace clic en "Guardar", el frontend revisa cuáles cajitas quedaron seleccionadas, extrae sus id_permisom y arma el arreglo para enviártelo en el JSON, por ejemplo: "idsPermisos": [1, 2].
